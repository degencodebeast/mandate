Mandate

Financial fault tolerance for autonomous agents.

One Intent. No blind retries.

Project description

Mandate protects an autonomous agent when a payment result becomes unknown. It records one economic Intent before payment authorization. It reserves the budget atomically. It checks the exact service authority. If value can have moved, Mandate blocks a new authorization for the same Intent. The agent can only WAIT or REQUEST_REVIEW.

Submission details

An agent can send a valid payment authorization and lose the response. The service can accept the payment while the application sees an error. A blind retry can pay twice for one business action. Mandate adds an economic safety boundary above the payment rail. A User creates a task-scoped Mandate. The Mandate sets the total budget, the per-call cap, the allowed service, and the expiry. The agent cannot create its own authority. Before value can move, Mandate admits one Intent, reserves budget, checks the exact service URL, and acquires one payment transition. Concurrent calls cannot authorize the same Intent twice. Concurrent Intents cannot spend the same remaining budget. If the result is unknown, Mandate freezes the Intent. It does not infer failure from a balance, amount, wallet, or time match. UNKNOWN permits WAIT or REQUEST_REVIEW only. Service switching occurs before authorization, after an exact final rejection, or for a separate Intent. The proof uses one real Circle Gateway USDC payment on Arc testnet. The official Gateway lookup returns the Payment Reference state. A separate Arc transaction stores the Receipt Anchor. These are different values. The response-loss case is injected after the economic action. It does not simulate the payment. REST is the stable interface. MCP is verified in integration tests through the official Python SDK. MCP exposes spend and status only.
